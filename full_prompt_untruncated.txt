**1.4 Registry audit script (prevents regression)**
Create `scripts/audit-registry.ts` and the script `pnpm registry:audit`:
```ts
import { readdirSync, readFileSync } from "node:fs";

const dir = "registry/generated";
let failed = 0;
const fail = (m: string) => { console.error("✗", m); failed++; };

for (const f of readdirSync(dir).filter((f) => f.endsWith(".json") && f !== "registry.json")) {
  const item = JSON.parse(readFileSync(`${dir}/${f}`, "utf8"));
  const declared = new Set<string>(item.dependencies ?? []);
  const src: string = item.files.map((x: { content: string }) => x.content).join("\n");
  if (src.includes("\r")) fail(`${item.name}: CRLF line endings`);
  for (const [, spec] of src.matchAll(/from\s+["']([^"']+)["']/g)) {
    if (spec.startsWith("@buildora/")) { fail(`${item.name}: workspace import ${spec}`); continue; }
    if (spec.startsWith(".") || spec.startsWith("@/") || spec === "react") continue;
    const pkg = spec.startsWith("@") ? spec.split("/").slice(0, 2).join("/") : spec.split("/")[0];
    if (!declared.has(pkg)) fail(`${item.name}: undeclared dependency ${pkg}`);
  }
  if (/\[--b-/.test(src)) fail(`${item.name}: legacy arbitrary value [--b-…] (use var() with type hint)`);
  if (/#[0-9a-fA-F]{3,8}\b|\bwhite\/\[|\btext-white\b/.test(src)) fail(`${item.name}: hard-coded colour`);
  if (!(item.files ?? []).every((x: { target?: string; path: string }) => x.target || !/\/index\.tsx$/.test(x.path)))
    fail(`${item.name}: ambiguous index.tsx without target`);
}
process.exit(failed ? 1 : 0);
```
The last three rules (legacy `[--b-`, hard-coded colours, ambiguous `index.tsx`) start as warnings until Phase 3 and 1.3 land, then become errors. Add to CI.

## PHASE 4: Motion engine and performance

**4.1 Shared frame scheduler (`packages/animations/src/scheduler.ts`)**
```ts
type FrameCb = (dt: number, now: number) => void | false; // return false to unsubscribe
const subs = new Set<FrameCb>();
let raf = 0, last = 0;

function loop(now: number) {
  const dt = Math.min((now - last) / 1000, 1 / 30);
  last = now;
  for (const cb of [...subs]) if (cb(dt, now) === false) subs.delete(cb);
  raf = subs.size ? requestAnimationFrame(loop) : 0;
}
export function subscribeFrame(cb: FrameCb) {
  subs.add(cb);
  if (!raf && !document.hidden) { last = performance.now(); raf = requestAnimationFrame(loop); }
  return () => { subs.delete(cb); };
}
if (typeof document !== "undefined")
  document.addEventListener("visibilitychange", () => {
    if (document.hidden) { cancelAnimationFrame(raf); raf = 0; }
    else if (subs.size && !raf) { last = performance.now(); raf = requestAnimationFrame(loop); }
  });
```
One rAF for the whole page; it stops when there are no subscribers.

**4.2 Spring integration (`springs.ts`), replacing the `dt`-less `springStep`**
```ts
export type Spring = { k: number; c: number; m?: number };
export function stepSpring(s: { x: number; v: number }, target: number, sp: Spring, dt: number) {
  const m = sp.m ?? 1, h = 1 / 120;
  for (let t = dt; t > 0; t -= h) {
    const d = Math.min(h, t);
    s.v += ((sp.k * (target - s.x) - sp.c * s.v) / m) * d;
    s.x += s.v * d;
  }
}
export const isAtRest = (s: { x: number; v: number }, target: number, eps = 0.05) =>
  Math.abs(s.v) < eps && Math.abs(target - s.x) < eps;
```
Keep a deprecated `springStep` wrapper for one minor version. Note: with mass 1, critical damping is `2·√k` (≈ 32 for k = 260), so `c = 22` is underdamped (ζ ≈ 0.68). That is the intended slight overshoot, so fix any comment claiming "critically damped".
Unit test: simulating the same spring at 60 Hz and 144 Hz for 2 s reaches the same position within 0.5 px.

**4.3 Hooks (`packages/hooks`)**

- `useElementRect(ref)`: ResizeObserver plus passive scroll/resize invalidation, cached; consumers never call `getBoundingClientRect` in a frame callback.

### 5.1 Magnetic Button (F-14)

Defects to fix:
- (a) The listener is on the button, so proximity never triggers outside it (the `radius` prop only shapes falloff inside the button).
- (b) "Spring" only advances on pointer events (3 `springStep`s per event, no `dt`); speed depends on mouse polling rate; it freezes mid-flight when the pointer stops.
- (c) Leaving hard-snaps (`style.transform = ""`, no transform transition), so there is no spring return.
- (d) The rect is read from the transformed element, so the centre moves with the button (feedback loop).
- (e) `glow` is destructured and never used, while the docs show a Glow control.
- (f) No `forwardRef`; `{...rest}` after `ref`; no default `type="button"`; permanent `will-change-transform`; pointless `useReducer` re-render.
- (g) Variant `iris` does not use the iris token; Tailwind syntax per F-17.

Reference implementation (adapt class strings/variants to existing styles; use tokens and the syntax from Task 3.3):
```tsx
"use client";
import * as React from "react";
import { cn } from "@/lib/utils";
import { useReducedMotion } from "@/hooks/use-reduced-motion";

export interface MagneticButtonProps extends React.ComponentPropsWithoutRef<"button"> {
  strength?: number;   // 0..1
  radius?: number;     // px from the button's EDGE where the pull starts
  glow?: boolean;
  variant?: "accent" | "ghost" | "iris";
}
const K = 260, C = 22; // mass 1 → ζ≈0.68, slight overshoot

export const MagneticButton = React.forwardRef<HTMLButtonElement, MagneticButtonProps>(
  ({ strength = 0.35, radius = 120, glow = true, variant = "accent", type = "button", className, ...props }, fwd) => {
    const ref = React.useRef<HTMLButtonElement>(null);
    React.useImperativeHandle(fwd, () => ref.current!, []);
    const reduced = useReducedMotion();

    React.useEffect(() => {
      const el = ref.current;
      if (!el || reduced) return;
      if (!matchMedia("(hover: hover) and (pointer: fine)").matches) return;
      const s = { x: 0, y: 0, vx: 0, vy: 0, tx: 0, ty: 0 };
      let raf = 0, last = 0;

      const tick = (now: number) => {
        const dt = Math.min((now - last) / 1000, 1 / 30); last = now;
        s.vx += (K * (s.tx - s.x) - C * s.vx) * dt;
        s.vy += (K * (s.ty - s.y) - C * s.vy) * dt;
        s.x += s.vx * dt; s.y += s.vy * dt;
        const rest = Math.hypot(s.vx, s.vy) < 0.05 && Math.hypot(s.tx - s.x, s.ty - s.y) < 0.05;
        el.style.transform = rest && !s.tx && !s.ty ? "" : `translate3d(${s.x}px,${s.y}px,0)`;
        if (rest) { el.style.willChange = ""; raf = 0; } else raf = requestAnimationFrame(tick);
      };
      const wake = () => { if (!raf) { last = performance.now(); el.style.willChange = "transform"; raf = requestAnimationFrame(tick); } };

      const onMove = (e: PointerEvent) => {
        const r = el.getBoundingClientRect();
        const cx = r.left + r.width / 2 - s.x, cy = r.top + r.height / 2 - s.y; // rest centre
        const dx = e.clientX - cx, dy = e.clientY - cy;
        const ex = Math.max(Math.abs(dx) - r.width / 2, 0), ey = Math.max(Math.abs(dy) - r.height / 2, 0);
        const t = Math.max(0, 1 - Math.hypot(ex, ey) / radius);
        s.tx = dx * strength * t; s.ty = dy * strength * t;
        if (t > 0 || s.tx || s.ty || raf) wake();
      };
      addEventListener("pointermove", onMove, { passive: true });
      return () => { removeEventListener("pointermove", onMove); cancelAnimationFrame(raf); el.style.transform = ""; el.style.willChange = ""; };
    }, [radius, strength, reduced]);

    return <button ref={ref} type={type} data-glow={glow || undefined} className={cn(/* base + variant + glow ::after via data-glow */ className)} {...props} />;
  }
);
```
Then swap the private rAF for `subscribeFrame` and the per-event `getBoundingClientRect` for the cached `useElementRect` (Phase 4), and use one shared window listener when many instances exist. Implement `glow` as a `::after` radial-gradient pseudo-element that fades via `opacity` (compositor-friendly) driven by `data-glow`, or remove the prop and the docs control.

Acceptance tests (Playwright/Vitest):
- Pointer 10 px outside the edge produces a non-zero translate within 300 ms; pointer beyond `radius` produces none.
- Pointer leaves: returns to `translate(0,0)` within 800 ms with overshoot ≤ 15% of the displacement.
- `prefers-reduced-motion: reduce`: transform is never set.
- Coarse pointer/touch emulation: no window listener attached.
- `ref` forwarding works; default `type="button"` (does not submit a form); `disabled` does not move.
- Focus ring visible under keyboard focus; axe 0 violations.
- Docs controls (strength, radius, variant, glow) each change observable behaviour.

### 5.2 Slingshot OTP (F-15, F-24)

Defects to fix:
- (a) `mode` defaults to `"game"`, and game mode has no `<input>`. No keyboard, paste, autofill or `autocomplete="one-time-code"`. This contradicts "real inputs, paste, SR fallback underneath" and the docs' own principle.
- (b) Rocks are single-use (`"done"` → `display:none`; `pointerDown` only accepts `ground`/`shot`), and `onClear` never restores them. Codes with repeated digits (e.g. `112233`) cannot be entered; Clear leaves fewer digits. **(verify)**
- (c) Physics is per-frame (`x += vx; vy += 0.5`): about 2× faster at 120 Hz.
- (d) `getBoundingClientRect()` for every empty target on every flight frame.
- (e) Hard-coded geometry (SVG frame at `x=180`, rocks at `80 + col*45`) versus `width/2` slingshot position; breaks below 360 px.
- (f) Hard-coded colours (`#050505`, `#111`, `text-white`, acid `rgba(...)`): dark-only, ignores accent.
- (g) Standard mode: `maxLength` truncates a pasted `"123 456"` to `"123 45"` (5 digits after filtering); `<label>` has no `htmlFor`; toggle button has no `type="button"` / `aria-pressed`; fake caret blinks forever even when unfocused; no `invalid`, `disabled`, `name`, `aria-live`; no reduced-motion handling.
- (h) The rAF effect deps are `[length, digits, onHit]`, so it restarts whenever the parent re-renders.
- (i) `framer-motion` used but undeclared (F-03).

Target architecture:
- Public API: `length`, `value`, `defaultValue`, `onChange`, `onComplete`, `name`, `disabled`, `invalid`, `autoFocus`, `label`, `aria-describedby`, `gameEnabled?: boolean` (default `true`, hidden automatically under reduced motion).
- **Always render a real `<input>`** (single, visually hidden but focusable, `inputMode="numeric"`, `autoComplete="one-time-code"`, `pattern="\d*"`, no `maxLength`) as the single source of truth. The visual digit cells mirror its value (`aria-hidden`).
- Handle paste with `onPaste`: strip non-digits **before** truncating to `length`.
- **The game is an optional second input method** that writes into the same value. Default view is the standard cells; a labelled toggle (`type="button"`, `aria-pressed`) opens the game. The game layer is `aria-hidden` and never the only way to enter a code.
- Game has **unlimited ammo**: a rock respawns at its base after a hit. Clear and per-digit Backspace exist. Repeated digits work.
- Fixed-timestep physics in px/s (preserves the current 60 Hz feel): gravity `1800`, launch velocity `pull × 15`, restitution `0.4`. Use `STEP = 1/120`, accumulate `dt` (clamped to 0.1 s), and run `while (acc >= STEP)`.
- Geometry derived from the measured container (ResizeObserver, container-local coordinates) and an SVG `viewBox`; no fixed pixel constants.
- Cache target rects; latest-ref pattern for `onHit` and `digits` so the loop mounts once.
- Tokens only; glow via `color-mix(in oklab, var(--b-accent) 30%, transparent)`.
- `role="group"` + `aria-labelledby` (label wired to the input), `aria-live="polite"` announcing "3 of 6 digits entered", `aria-invalid` when `invalid`.
- Under `prefers-reduced-motion`: game toggle hidden; blink caret only while focused and only when motion is allowed.
- The homepage demo renders the **exact** registry component (F-24).

Acceptance tests:
- Paste `"123 456"` → value `123456`; paste `"12-34-56"` → `123456`.
- Game mode: `112233` can be entered; Clear restores all rocks; Backspace removes one digit.
- Physics determinism: simulate the same shot at 60 Hz and 144 Hz; landing x differs by ≤ 2 px.
- `<label>` click focuses the input; form submission includes `name=value`; `disabled` blocks both modes.
- Reduced motion: no game toggle, no infinite animation.
- Works at container widths 280 / 320 / 360 / 480.
- Light mode and all four accents render correctly; axe 0 violations.
